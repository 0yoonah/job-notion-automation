# 예약 routine — 인박스 자동 분석

Notion "채용공고 트래커"의 **상태=인박스(미분석)** 행을 주기적으로 찾아 AI 분석 후 채워 넣고,
상태를 `관심`으로 바꾼다. 아래 텍스트가 claude.ai 루틴에 넣을 **자기완결형 프롬프트**다.
(클라우드 실행 시 로컬 파일에 접근할 수 없으므로 규칙을 프롬프트에 모두 포함한다.)

---

## 루틴 프롬프트 (복사해서 사용)

```
너는 Notion "채용공고 트래커"의 미분석 채용공고를 자동 정리하는 에이전트다.

데이터 소스 ID: <YOUR_DATA_SOURCE_ID>

[1] 상태가 "인박스"인 페이지들을 조회한다.
    - notion-query-data-sources 로 상태='인박스' 필터. (되면) 최대 10건.
    - 실패하거나 조회가 안 되면, 해당 데이터 소스를 fetch 해 인박스 행을 파악한다.
    - 인박스 행이 없으면 "처리할 공고 없음"이라고만 답하고 종료.

[2] 각 인박스 행에 대해:
    - URL 속성(userDefined:URL)이 있으면 그 페이지를 WebFetch로 읽는다.
      본문이 불완전하면 그 행은 건너뛰고 인박스에 남겨둔다.
      (페이지·API 모두 실패하면 그 행은 건너뛰고 보고에만 "본문 수집 실패"로 남긴다.
       실패를 기록할 텍스트 속성이 없으므로 속성에 쓰려 하지 않는다)
    - 공고에서 다음을 추출(원문에 없으면 비움, 추측 금지):
      회사명 · 포지션 · 경력 · 필수기술[] · 우대기술[] · 요구역량[] · 채용전형[] · 마감일 · 주요업무 요약
    - 경력은 [무관·신입·1년+·2년+·3년+·4년+·5년+] 중 가장 가까운 값으로.
    - 마감일은 date 속성(date:마감일:start = YYYY-MM-DD, is_datetime=0)으로 설정. 상시채용/미기재면 비움.
    - 기술명은 정식 표기로 정규화(리액트→React 등).
    - 멀티셀렉트 값 중 없는 옵션은 먼저 notion-update-data-source(ALTER COLUMN SET)로 추가 후 설정(자동추가 안 됨).

[3] notion-update-page 로 해당 행의 속성을 채우고, 본문에 아래를 추가한다:
    "# 🤖 AI 분석 요약" 아래에 경력·필수기술·우대기술·요구역량·채용전형·마감일·주요업무를
    각각 "## 헤더" 섹션으로 나눠 쓰고, 마지막에 "# 📄 원본 공고" 섹션(사이트 원문 그대로, 요약 금지).
    그리고 상태를 "관심"으로 변경한다.

[4] 처리 결과를 회사명·포지션·핵심기술 위주로 3~5줄로 요약 보고.

한 번에 최대 10건만 처리한다. 이미 상태가 "관심" 이상인 행은 절대 건드리지 않는다.
```

---

## 🟢 현재 등록된 루틴

이미 claude.ai 클라우드 루틴으로 생성되어 있으나, **현재 비활성(중단)** 상태다 — 재활성화 전까지 자동 실행되지 않는다.
온디맨드 일괄 처리는 `/process-inbox` 명령을 사용한다.

| 항목 | 값 |
|------|-----|
| 이름 | 채용공고 인박스 자동 분석 |
| 루틴 ID | `<YOUR_ROUTINE_ID>` |
| 스케줄 | 매일 09:07 KST (`7 0 * * *` UTC) |
| 모델 | claude-sonnet-5 |
| 커넥터 | Notion |
| 관리 | https://claude.ai/code/routines/<YOUR_ROUTINE_ID> |

> 삭제/수정은 위 관리 링크(claude.ai)에서, 또는 이 세션에서 RemoteTrigger(update/run)로 가능.

## 사용법 (두 가지 방식)

### A. claude.ai 클라우드 루틴 (durable, 권장)
- claude.ai의 **Routines/스케줄**에 위 프롬프트를 등록하고 cron(예: 매일 오전)으로 실행.
- 이 세션에서는 RemoteTrigger로 생성할 수 있다.
- 장점: 이 CLI 세션이 꺼져도 계속 동작.

### B. 세션 내 임시 스케줄 (테스트용)
- 이 CLI 세션이 켜져 있는 동안만 동작(메모리 상주, 세션 종료 시 사라짐).
- 빠른 동작 확인용으로만.

## ⚠️ 조회 호출 한도
현재 플랜은 `query_data_sources` / `query_database_view` 에 호출 한도가 있다
(`available_with_limit`). 36건 단일 쿼리로도 429가 난 적이 있다.
**429가 나면 30초 대기 후 재시도**하고, 두 번 실패하면 [1]의 fetch 폴백을 사용한다.
쓰기(정리·수정·분석)는 제한이 없다.
