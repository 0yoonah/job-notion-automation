# 채용공고 분석 스펙 (Single Source of Truth)

온디맨드 명령(`/analyze-job`)과 예약 routine이 **공통으로 참조**하는 추출·매핑 규칙.
분석 엔진은 별도 API 없이 **Claude(MCP 세션)** 자체가 수행한다.

---

## 1. 대상 Notion 데이터베이스

| 항목 | 값 |
|------|-----|
| 데이터베이스 | 채용공고 트래커 |
| Database URL | `<YOUR_NOTION_DB_URL>` |
| **data_source_id** | `<YOUR_DATA_SOURCE_ID>` |

페이지 생성 시 `parent`는 `{ "data_source_id": "<YOUR_DATA_SOURCE_ID>" }`.

> **설정값 교체**: `<YOUR_...>` 는 각자 환경 값으로 바꿔야 동작한다.
> - `data_source_id` — Notion에서 해당 DB를 `notion-fetch` 하면 `<data-source url="collection://...">` 에서 확인.
> - 루틴 ID — https://claude.ai/code/routines 에서 확인.

## 2. 속성(property) 매핑

> ⚠️ URL 속성의 실제 키는 **`userDefined:URL`** (표시 이름은 "URL"). 그대로 사용해야 검증 오류가 안 난다.

| 속성 키 | 타입 | 채우는 값 |
|---------|------|-----------|
| `회사명` | title | 회사명 (필수) |
| `포지션` | text | 포지션명 |
| `상태` | select | 아래 §4 규칙 |
| `경력` | select | `무관·신입·1년+·2년+·3년+·4년+·5년+` 중 가장 가까운 값. 미기재 시 비움 |
| `필수기술` | multi_select | 필수 기술 스택 (정규화된 정식 명칭) |
| `우대기술` | multi_select | 우대 기술 스택 |
| `요구역량` | multi_select | 요구 역량 키워드 (예: 협업, 문제해결) |
| `채용전형` | multi_select | 전형 절차 (예: 서류·코딩테스트·과제·1차면접·2차면접·임원면접·컬처핏). 공고에 없으면 비움 |
| `마감일` | date | 지원 마감일. 설정 시 `date:마감일:start`에 ISO 날짜(YYYY-MM-DD), `date:마감일:is_datetime`=0. 상시채용/미기재면 비움 |
| `주요업무` | text | 주요 업무 2~3문장 요약 |
| `userDefined:URL` | url | 원본 공고 링크 (있을 때만) |
| `등록일` | created_time | 자동 (설정 불필요) |
| `지원일` / `메모` | date / text | 사용자가 수기 관리 (자동화는 건드리지 않음) |

> ⚠️ 멀티셀렉트는 **없는 옵션이 자동 추가되지 않는다.** 시드에 없는 값을 넣으면 검증 오류가 난다.
> 값을 설정하기 전에 `notion-update-data-source`(`ALTER COLUMN "속성" SET MULTI_SELECT(기존+신규 옵션 전체)`)로
> **먼저 옵션을 추가**한 뒤 값을 채운다.

기술명은 정식 표기로 정규화한다 (예: 리액트→React, 타입스크립트→TypeScript, 넥스트→Next.js).

## 3. 페이지 본문(content) 템플릿

Notion-flavored Markdown으로 아래 구조를 채운다.

```
# 🤖 AI 분석 요약

## 경력
{경력}

## 필수 기술
{필수기술 쉼표 나열}

## 우대 기술
{우대기술 쉼표 나열}

## 요구 역량
{요구역량 쉼표 나열}

## 채용 전형
{채용전형 쉼표 나열}

## 마감일
{마감일 YYYY-MM-DD 또는 "상시채용/미기재"}

## 주요 업무
{주요업무 요약}

---

# 📄 원본 공고
{사이트 공고 원문 그대로 — 요약하지 않는다}
```

## 4. 상태(상태) 규칙

- **온디맨드**로 새로 분석해 등록할 때 → `관심`
- **URL만 먼저 담아둔 미분석 행** → `인박스`
- 예약 routine이 인박스 행을 분석 완료하면 → `관심`으로 변경
- 그 이후 진행 상태(지원예정~불합격)는 **사용자가 보드에서 수기로** 이동

## 5. 원문에 없는 정보

추측하지 않는다. 알 수 없으면 해당 속성은 비우고, 본문 요약에도 넣지 않는다.
회사명을 도저히 알 수 없으면 "(회사명 미상)"으로 title을 채운다.
